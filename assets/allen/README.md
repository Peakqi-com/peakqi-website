# Allen 的美術資產

| 檔案 | 來源 | 用途 |
|---|---|---|
| `workshop.webp` | `assets/svg/robot_removed_web_background.svg` 裡內嵌的 PNG | 第一幕的背景 |
| `turnaround.webp` | `assets/svg/robot_turnaround_8_views_exact.svg` 裡內嵌的 PNG | 轉身那一段的六格精靈圖 |
| `room/stage.webp` | 原圖 + 重畫的空房間 | 房間底板(挖掉會動的元件與雲) |
| `room/parts/*.webp` | 差異遮罩切出來 | 12 個會動的元件 + 3 朵完整的雲 |
| `room/sky-mask.webp` | 原圖看得到天空的地方 | 雲的可見範圍遮罩(窗緣是軟的、建築輪廓是硬的) |
| `room/grade/<時段>-m.webp` | 打光運算 | 天色:multiply 那一層(壓暗) |
| `room/grade/<時段>-s.webp` | 同上 | 天色:screen 那一層(提亮,霓虹在這裡) |
| `room/grade/<時段>-off.webp` | 同上 | 那個時段的關燈版(multiply) |

`workshop.webp` 現在只給 reduced-motion 的靜態畫面與開發預覽頁用(它是完整的原圖,
一個請求就好);正式的動態場景走 `room/stage.webp` + 12 個零件。
reduced-motion 那張也會疊天色的分級圖(和動態版同一份、同一個裁切方式),
只是不能切換 —— 關掉動畫的意思是「不要動」,不是「永遠是白天」。

## workshop.webp 怎麼來的
原稿是一張 3.8 MB 的 SVG,裡面包著一張 1254×1254 的 base64 PNG(機器人已被去掉的工作間)。
那個尺寸不能上線,所以轉成同解析度的 WebP:

```
magick <原始 PNG> -strip -resize 1254x1254 -define webp:method=6 -quality 86 workshop.webp
```

3.8 MB → 103 KB,平塗卡通畫面在 q86 下與原圖肉眼無差(RMSE 1.3%,全落在邊緣抗鋸齒上)。

## 機器人本體不在這裡
角色是向量,直接編成 `allen-art.js`(見根目錄 README「如何替換 Allen」)。
原稿與分解圖留在 `assets/svg/`,只是素材備份,線上不會載入。

## turnaround.webp 怎麼來的
原稿是 2048×682 的八視角 PNG(一樣包在 SVG 殼裡)。處理了三件事:

1. **去背**:不能直接砍白色 —— 眼白、胸板、鞋底也是白的。改成先找出所有白色連通區塊,
   碰到畫面邊界的算背景;另外「又高又大」的封閉白色口袋(135° 與 225° 兩格的雙腿之間,
   高 160+ px)也算背景,而圖形自己的白最高只有胸板約 40px,兩者分得很開。
2. **對齊**:每一格量出「最底下 34 列(鞋子)的水平中心」當重心軸,再把八格都以那條軸
   置中重排。原圖的八個圖形既不是等距也不是置中的。
3. **裁格**:只留 45°–270° 六格。理由見根目錄 README。

換圖的話這三步要重跑,腳本沒有留在 repo 裡(一次性的資料清理,留著反而會誤導成建置流程)。

## room/ 怎麼來的
`python tools/gen-allen-room-assets.py`(不是網站建置流程,換素材時手動跑一次)。
它同時產生根目錄的 `allen-room-parts.js`(每個元件的貼圖框),程式和資產不會走鐘。

輸入兩張:
- `robot_workshop_strict_source_package/source_original_embedded.png` — 原始場景
- `robot_workshop_background_filled.svg` — 美術重畫的「空房間」(可動物件都拿掉、洞補好)

關鍵做法(細節寫在腳本檔頭):
- **元件遮罩不用套件切片的 alpha**。那些切片系統性偏小,物件右側的暗面與投影沒收進去;
  用它當遮罩的話那圈深色會留在底板上不動,物件一擺動就變成雙重輪廓(300px 下看得見)。
  改成用「原圖 vs 空房間」的差異當遮罩,描邊與投影整組跟著物件走。套件的 alpha 只當種子。
- 差異圖在相鄰元件之間是連通的(空房間把 22 個全拿掉了),所以要排除「別人的地盤」,
  不然按鈕的連通塊會沿著控制台整片淹出去(418px → 5052px)。
- 底板只在遮罩內換成空房間的像素,其餘保留原圖 —— 空房間是重畫的,牆面接縫差幾 px,
  整張換掉沒被拿走的東西會集體位移。換進去前先做色調補償,取樣圈要避開其他元件。
- 遮罩是二值不羽化,所以「底板 + 元件貼回原位」在數學上等於原圖。腳本自己驗 RMSE,
  超過 3.0 就中止(目前 2.83,剩下的是 webp 量化)。

## 雲怎麼來的
雲不在套件裡(它畫死在背景)。產生器自己分:平塗白雲配平滑漸層的天空是最好分的情況。

**只有輪廓完整的雲會動。** 雲在靜止畫面裡看得到的形狀,是「雲」和「擋住它的東西」的交集
—— 畫布左緣、前面那座白塔,都會在 alpha 上烤出一條直線。貼圖會動、擋住它的東西不會動,
那條線就走進開闊的天空變成一刀切口(這就是「雲被切一半」)。所以帶著人造直邊的雲不讓它動,
留在底板上當畫的一部分(靜止的話那條線只是原稿的構圖),但仍然算進可見天空,好讓會飄的雲
從它前面過去而不是被它咬掉一塊。兩道關卡量出來分得很開:

| | 四周開闊度 | 人造直邊 / 高度 |
|---|---|---|
| 完整的雲(會飄) | 0.56–0.85 | 0.13–0.23 |
| 被畫布或塔切過的雲(不動) | 0.75–1.00 | 0.85 / 0.99 |
| 建築的白色本體 | 0.00–0.28 | — |

其他三個關卡:
- 白色門檻只抓得到雲的核心,柔邊(白往藍過渡那一圈)會留在底板上 —— 雲飄走就是一條
  直線切口。所以從核心往外長到真正的天空藍,但要限制亮度(建築的深色描邊會擋住)
  和距離(最多 6px)—— 沒有距離上限會沿著白色建築整片長出去,城市的塔也是白的。
- 貼圖要「自己帶著柔邊走」:遮罩往外放 3px、底板挖掉的洞再往外 2px。只挖不帶的話,
  雲飄走之後會在原地留下一圈自己的輪廓;帶了但底板沒挖乾淨的話,靜止時那圈會露在外緣。
- 雲的可見範圍做成遮罩(`sky-mask.webp`)而不是橢圓:一次解掉兩件事 —— 雲不會飄到
  窗框上,而且雲不會蓋住城市(雲在城市後面)。遮罩用形態學閉合而不是 fill_holes ——
  後者會把圓頂的白色高光當成洞補進來,雲飄過去會有一塊白露在圓頂上。
  **遮罩在窗緣那一側是軟的、在建築輪廓那一側是硬的**:雲被塔擋住要乾淨俐落,
  飄出窗緣則要慢慢隱沒 —— 硬邊會把雲削成一個平口的方塊。

## 窗口的圓是量出來的,不是填的
`fit_aperture()`:沿著每一列往右找「最後一個天空像素」,而且它右邊幾格內要有窗框的深色
輪廓線;上下緣同理掃每一行。再用最小平方擬合圓,反覆丟掉離群點。**窗是圓的不是橢圓的**
—— 殘差 1.2 px 就是證據(p95 2.3 px,239 個邊界點)。

以前這裡是手填的橢圓,系統性小 13–38 px。那一個數字同時造成三個看得見的缺陷:
雲在真正的窗緣之前就被切成平口、最外圈的天空拿不到室外的分級(黃昏會沿著窗框留下一條
薄荷色的邊)、底板上還殘留半朵雲。量不出圓就中止,不要用猜的數字繼續。

## 天空遮罩為什麼要用顏色篩
建築上那些「夠藍」的窗格會通過顏色門檻變成孤島(量到 78 個),而孤島會被當成天空塗上
天空漸層 —— 黃昏是一塊塊土黃、夜裡是一塊塊深藍,那就是塔身上那層看起來很髒的斑點。
但也不能只留最大塊:塔與塔之間的天空被建築切成好幾塊,那些是真的。
判準是顏色:拿最大那塊算出「每一列的天空色」當參考,再看每個孤島差多遠 ——
塔間的天空差 22,建築窗格差 118 以上,中間空得很乾淨。

## 天色怎麼來的(黃昏 / 夜晚 / 關燈)
先把原圖拆成「環境光 + 檯燈」:檯燈的光是個以燈頭為中心的衰減場,減掉就是環境光。
然後環境光按時段重打(天空換成垂直漸層、城市壓成剪影再點亮霓虹、室內換色並讓
「離窗越遠越暗」),檯燈最後單獨加回去 —— 夜裡它是主光,不能跟著環境一起暗。
關燈就是不加回去。全部是打光運算,像素來源只有原圖。

輸出不是三張底板,是每個時段兩張分級圖:
```
B = 原圖 × M          M = clamp(目標 / 原圖, 0, 1)      ← multiply 只能壓暗
輸出 = 1 − (1−B)(1−S)  S = 1 − (1−目標) / (1−B)          ← screen 負責提亮
```
這是閉式解不是近似(產生器自己驗,誤差 > 1 階就中止)。網頁端把這兩張疊在
「房間 + Allen」整疊的最上面,一次把所有東西一起調到同一個時段 —— 換底板的話
只有底板會變,元件、雲和角色都還是白天的顏色。

兩個非直覺的地方:
- **分級要是位置的函數,不能是像素值的函數**。雲飄過去、元件擺動時,底下露出來的
  像素才不會被套上前一個物件的分級而留下鬼影。所以室內是位置場、天空是垂直漸層,
  只有畫死不動的城市才按像素值分。天空區的參考影格取「底板」不取原圖 —— 底板的雲
  已經拿掉,分級才會是平滑的天空。
- **純白像素要特判**。`on == B` 的時候 S 會算成 0/0 = 1,那一層就把輸出釘死在白色,
  關燈那一層再怎麼乘都壓不下來(白色地板整片關不掉)。

存檔時有損與無損各壓一次留小的:夜晚的 screen 圖幾乎全黑只有霓虹,無損反而又小又準
(15.9KB,而且高對比邊緣不會被色度取樣糊掉);黃昏的 screen 圖整片天空都有值,
有損才划算。

城市那一段要「重打光」不能「每個通道各乘一個係數」。乘係數的話藍色的東西會直接變成黑洞
(圓頂在黃昏變成一片黑鰭),而且原稿的明暗關係整個被壓平 —— 使用者說的「粗糙、爆掉」
跟「不夠飽滿」都是這裡來的。改成把明度與色度拆開:明度重新映射到這個時段的區間
(保住原稿的立體感),色度變淡並整體偏向這個時段的色溫。量得出來的差別:

| | 建築 vs 描邊 | 建築 vs 天空 |
|---|---|---|
| 白天 | +118 | +40 |
| 第一版夜晚 | **−108**(整座城市變成閃爍的線框) | +13 |
| 現在夜晚 | +11 | +71 |

霓虹只認成片的色塊:門檻 b−r>60(city 藍色像素的 b−r 是雙峰的,20~50 那一峰是塔身的
藍灰陰影、65 以上才是真正的窗格)、開運算 r=2、連通塊面積 45–520 px(上限是要擋掉
圓頂那種大片的藍色斜面 —— 把整片斜面點成霓虹會變成一塊貼上去的螢光色)。

**只有夜晚有關燈分級圖。** 這裡連續踩了三次才對:
先是白天只扣掉檯燈的「直射」那一份,那一區只暗 17.9 階,戳了等於沒反應;
補上散射與暖色偏移之後又反過來,關燈在畫面上留下一團放射狀的黑色光暈
(離燈頭 300 px 還在暗 17.5 階);把範圍收到 143 px 還是看得出來 ——
**任何放射狀的暗場都會被看成憑空多出來的陰影,收得再小都一樣。**

正確的答案是:房間亮的時候關掉一盞桌燈,房間本來就不會變暗。所以白天與黃昏
乾脆不出關燈分級圖(`room_off: False`),切換時只有檯燈自己的像素會變 ——
燈罩不再發亮、燈身暗一階,那才是「就關掉而已」。夜裡才是主光,才有整室的變化。

瀏覽器上實測「開燈 → 關燈」在各個半徑上的亮度變化(canvas px):

| 離燈頭 | 60 | 120 | 180 | 240 | 320 | 450 |
|---|---|---|---|---|---|---|
| 白天 | −2.5 | +0.2 | +0.3 | +0.9 | −0.3 | −1.5 |
| 黃昏 | +0.5 | +0.6 | +1.4 | −0.5 | −0.9 | +0.2 |
| 夜晚 | **+115** | +94 | +68 | +52 | +32 | +15 |

白天與黃昏那兩排全是雜訊(Allen 自己在動);燈罩那一小塊則是白天 −12 階、
黃昏 −7、夜晚 −110 —— 燈確實滅了,房間沒動。

燈罩本身則要反過來加一份。原稿是把燈畫成亮著的 —— 開口那一塊是奶油色、中間還有一團
白色的燈泡,不加光也還是那樣。所以關燈時在開口那一小塊(40×24 px)疊兩層:
`saturation` 把顏色抽掉、`multiply` 壓暗,燈罩與燈泡就變成沒通電的灰。

遮罩是 **軟邊橢圓 × 檯燈貼圖自己的明度**(`softLit()`)。兩層都必要:橢圓決定大概在
哪裡,貼圖的明度決定「亮的地方才吃得到」,而貼圖以外是全透明(明度 0)。橢圓要收在
燈罩口 —— 放大到整個鐘罩的話,柔邊會在灰色金屬上抹出一團模糊的暗污。
遮罩的明度要指定 `color-interpolation="sRGB"`:預設是在 linearRGB 算,各家瀏覽器不一致。

還有一個一直沒被發現的元凶:`g.lamp.style.opacity = 0.72 + lampT * 0.28`。關燈時整支
燈變成 72% 半透明,底板上「挖掉檯燈」的那塊修補痕就從燈身透出來 —— 燈看起來糊糊的、
四周還帶一圈暗邊。**要暗的是「光」不是「不透明度」**,那一行已經刪掉。

實測(白天,開燈 → 關燈):燈泡 L217→139、鐘罩 −4 / −13、紅色燈臂 −5、
左邊的牆 +2、燈下的牆 −1 —— 燈滅了,牆沒動。

有一件事刻意不做:原稿把檯燈打在牆上與桌面上的光也畫進去了。要把那片光拿掉,就會在
牆上留下一團放射狀的暗場 —— 那正是前面被退回好幾次的黑色光暈。所以那片光留著。

網頁端也有一份要一起收:桌面那圈暖光橢圓(半徑 250,卡片上約 60 px)本來
跟著開關進出,那本身就是一團光暈。現在它乘上「夜晚的權重」,只在夜裡出場。
還有關燈的退路漸層 —— 原本「分級圖還在載」也會觸發,那半秒的漸層看起來就是
一團憑空出現的黑暈;改成只有「這個時段本來就該有圖、但載不到」才出場。

還有一道數學上的必要條件:**室內任何一點都不可以比白天的原圖亮**。不是為了寫實,是因為
一旦某個像素在「開燈」時被推到滿格,那裡的 screen 值就是 1,而 screen(任何東西, 1) 恆等於 1
—— 關燈那一層再怎麼乘都壓不下來(檯燈那一圈會關不掉,實測誤差 196 階)。所以在 0.8 倍
原圖之後平滑收斂到 0.98,不用硬切(硬切會留下一條邊)。

## 套件本身的兩個已知限制
- 切片偏小(見上),所以我們不直接用它的 alpha。
- `top_blue_monitor` 的切片邊緣是破的,`top_box_blue` / `top_box_red` 有白邊,
  這三個沒有列入會動的元件。
