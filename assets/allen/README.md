# Allen 的美術資產

| 檔案 | 來源 | 用途 |
|---|---|---|
| `workshop.webp` | `assets/svg/robot_removed_web_background.svg` 裡內嵌的 PNG | 第一幕的背景 |
| `turnaround.webp` | `assets/svg/robot_turnaround_8_views_exact.svg` 裡內嵌的 PNG | 轉身那一段的六格精靈圖 |
| `room/stage.webp` | 原圖 + 重畫的空房間 | 房間底板(挖掉會動的元件與雲) |
| `room/parts/*.webp` | 差異遮罩切出來 | 12 個會動的元件 + 3 朵雲 |
| `room/sky-mask.webp` | 原圖看得到天空的地方 | 雲的可見範圍遮罩 |
| `room/grade/<時段>-m.webp` | 打光運算 | 天色:multiply 那一層(壓暗) |
| `room/grade/<時段>-s.webp` | 同上 | 天色:screen 那一層(提亮,霓虹在這裡) |
| `room/grade/<時段>-off.webp` | 同上 | 那個時段的關燈版(multiply) |

`workshop.webp` 現在只給 reduced-motion 的靜態畫面與開發預覽頁用(它是完整的原圖,
一個請求就好);正式的動態場景走 `room/stage.webp` + 12 個零件。
reduced-motion 那張也會疊天色的分級圖(和動態版同一份、同一個裁切方式),
只是不能切換 —— 關掉動畫的意思是「不要動」,不是「永遠是白天」。

## workshop.webp 怎麼來的
原稿是一張 3.8 MB 的 SVG,裡面包著一張 1254×1254 的 base64 PNG(機器人已被去掉的工作間)。
那個尺寸不能上線,所以轉成同解析度的 WebP:

```
magick <原始 PNG> -strip -resize 1254x1254 -define webp:method=6 -quality 86 workshop.webp
```

3.8 MB → 103 KB,平塗卡通畫面在 q86 下與原圖肉眼無差(RMSE 1.3%,全落在邊緣抗鋸齒上)。

## 機器人本體不在這裡
角色是向量,直接編成 `allen-art.js`(見根目錄 README「如何替換 Allen」)。
原稿與分解圖留在 `assets/svg/`,只是素材備份,線上不會載入。

## turnaround.webp 怎麼來的
原稿是 2048×682 的八視角 PNG(一樣包在 SVG 殼裡)。處理了三件事:

1. **去背**:不能直接砍白色 —— 眼白、胸板、鞋底也是白的。改成先找出所有白色連通區塊,
   碰到畫面邊界的算背景;另外「又高又大」的封閉白色口袋(135° 與 225° 兩格的雙腿之間,
   高 160+ px)也算背景,而圖形自己的白最高只有胸板約 40px,兩者分得很開。
2. **對齊**:每一格量出「最底下 34 列(鞋子)的水平中心」當重心軸,再把八格都以那條軸
   置中重排。原圖的八個圖形既不是等距也不是置中的。
3. **裁格**:只留 45°–270° 六格。理由見根目錄 README。

換圖的話這三步要重跑,腳本沒有留在 repo 裡(一次性的資料清理,留著反而會誤導成建置流程)。

## room/ 怎麼來的
`python tools/gen-allen-room-assets.py`(不是網站建置流程,換素材時手動跑一次)。
它同時產生根目錄的 `allen-room-parts.js`(每個元件的貼圖框),程式和資產不會走鐘。

輸入兩張:
- `robot_workshop_strict_source_package/source_original_embedded.png` — 原始場景
- `robot_workshop_background_filled.svg` — 美術重畫的「空房間」(可動物件都拿掉、洞補好)

關鍵做法(細節寫在腳本檔頭):
- **元件遮罩不用套件切片的 alpha**。那些切片系統性偏小,物件右側的暗面與投影沒收進去;
  用它當遮罩的話那圈深色會留在底板上不動,物件一擺動就變成雙重輪廓(300px 下看得見)。
  改成用「原圖 vs 空房間」的差異當遮罩,描邊與投影整組跟著物件走。套件的 alpha 只當種子。
- 差異圖在相鄰元件之間是連通的(空房間把 22 個全拿掉了),所以要排除「別人的地盤」,
  不然按鈕的連通塊會沿著控制台整片淹出去(418px → 5052px)。
- 底板只在遮罩內換成空房間的像素,其餘保留原圖 —— 空房間是重畫的,牆面接縫差幾 px,
  整張換掉沒被拿走的東西會集體位移。換進去前先做色調補償,取樣圈要避開其他元件。
- 遮罩是二值不羽化,所以「底板 + 元件貼回原位」在數學上等於原圖。腳本自己驗 RMSE,
  超過 3.0 就中止(目前 2.48,剩下的是 webp 量化)。

## 雲怎麼來的
雲不在套件裡(它畫死在背景)。產生器自己分:平塗白雲配平滑漸層的天空是最好分的情況。
三個關卡:
- 白色門檻只抓得到雲的核心,柔邊(白往藍過渡那一圈)會留在底板上 —— 雲飄走就是一條
  直線切口。所以從核心往外長到真正的天空藍,但要限制亮度(建築的深色描邊會擋住)
  和距離(最多 6px)——沒有距離上限會沿著白色建築整片長出去,城市的塔也是白的。
- 篩選條件是「四周幾乎都是天空」:建築也是白的,但它們周圍有灰有紅有描邊。
- 雲的可見範圍做成遮罩(`sky-mask.webp`)而不是橢圓:一次解掉兩件事 —— 雲不會飄到
  窗框上(橢圓怎麼調都會差幾 px),而且雲不會蓋住城市(雲在城市後面,遮罩到建築
  輪廓自然被擋住)。遮罩用形態學閉合而不是 fill_holes ——後者會把圓頂的白色高光
  當成洞補進來,雲飄過去會有一塊白露在圓頂上。

## 天色怎麼來的(黃昏 / 夜晚 / 關燈)
先把原圖拆成「環境光 + 檯燈」:檯燈的光是個以燈頭為中心的衰減場,減掉就是環境光。
然後環境光按時段重打(天空換成垂直漸層、城市壓成剪影再點亮霓虹、室內換色並讓
「離窗越遠越暗」),檯燈最後單獨加回去 —— 夜裡它是主光,不能跟著環境一起暗。
關燈就是不加回去。全部是打光運算,像素來源只有原圖。

輸出不是三張底板,是每個時段兩張分級圖:
```
B = 原圖 × M          M = clamp(目標 / 原圖, 0, 1)      ← multiply 只能壓暗
輸出 = 1 − (1−B)(1−S)  S = 1 − (1−目標) / (1−B)          ← screen 負責提亮
```
這是閉式解不是近似(產生器自己驗,誤差 > 1 階就中止)。網頁端把這兩張疊在
「房間 + Allen」整疊的最上面,一次把所有東西一起調到同一個時段 —— 換底板的話
只有底板會變,元件、雲和角色都還是白天的顏色。

兩個非直覺的地方:
- **分級要是位置的函數,不能是像素值的函數**。雲飄過去、元件擺動時,底下露出來的
  像素才不會被套上前一個物件的分級而留下鬼影。所以室內是位置場、天空是垂直漸層,
  只有畫死不動的城市才按像素值分。天空區的參考影格取「底板」不取原圖 —— 底板的雲
  已經拿掉,分級才會是平滑的天空。
- **純白像素要特判**。`on == B` 的時候 S 會算成 0/0 = 1,那一層就把輸出釘死在白色,
  關燈那一層再怎麼乘都壓不下來(白色地板整片關不掉)。

存檔時有損與無損各壓一次留小的:夜晚的 screen 圖幾乎全黑只有霓虹,無損反而又小又準
(15.9KB,而且高對比邊緣不會被色度取樣糊掉);黃昏的 screen 圖整片天空都有值,
有損才划算。

## 套件本身的兩個已知限制
- 切片偏小(見上),所以我們不直接用它的 alpha。
- `top_blue_monitor` 的切片邊緣是破的,`top_box_blue` / `top_box_red` 有白邊,
  這三個沒有列入會動的元件。
