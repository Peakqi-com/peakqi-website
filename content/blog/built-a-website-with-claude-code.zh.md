我是 Allen,奇鋒國際的成員。在開始這個專案之前,我不會寫程式。

2026 年 7 月 16 日到 8 月 8 日之間,我用 [Claude Code](https://claude.com/claude-code) 從零蓋出公司官網 [peakqi.com](https://peakqi.com)——中英雙語共 32 個頁面、一段 three.js 的捲動分鏡、一層可以整個關掉的 WebGL 增強層,還有兩支自己寫的素材產生管線。

全部的程式碼都公開在 [GitHub](https://github.com/Peakqi-com/peakqi-website),提交歷史沒有整理過。

這篇不是成功心得,是工作記錄。

## 這個網站到底是什麼

不是模板。技術規格如下:

| 項目 | 內容 |
|---|---|
| 架構 | 原生 JavaScript,沒有前端框架。全站文案、價格、案例集中在單一 `content.js` |
| 首頁 | three.js 載入一顆 42 網格的相機 GLB 模型,隨捲動經歷組裝、拆解、零件說明、攤開藍圖、組回原型、翻面六個階段 |
| 渲染層 | `hero-engine.js`(Canvas 2D 分鏡)、`gl-engine.js`(WebGL 增強層,可整層關掉)、`micro-engine.js`(微互動) |
| 降級策略 | reduced-motion、save-data、deviceMemory < 4、寬度 < 900、context lost、shader 失敗——任一條件成立就自動降級,敘事完整保留 |
| 素材產生器 | `tools/gen-allen-art.mjs`(194 條 SVG 路徑歸位成九塊剛體)、`tools/gen-allen-room-assets.py`(40 層拆解,內建自我驗算) |
| 部署 | Vercel + GitHub Actions;表單走 serverless function 分流到 Google 試算表 / Email / Notion |
| 語言 | 繁體中文與英文,各 16 頁 |

![首頁分鏡第 02 階段「拆解」:相機本體與對應的字卡同時在場,右側是階段索引](/assets/blog/camera.webp)

想直接看成品的話,[首頁](/)、[案例](/cases)、[方案說明](/pricing) 是三個最能看出差異的地方。

## 卡住的那一天:7 月 19 日

我要把五支業務短片貼到 3D 相機背面的 LCD 螢幕上。聽起來是小事。那天的 60 個提交裡,超過一半在處理這一件事。

嘗試順序,照 commit 記錄:

1. three.js `VideoTexture` 貼在平面上 → 影片溢出螢幕
2. 無盡調整定位參數(`vpx0.88/vpy-0.06`、`vpx0.667/vpy-0.251`、`vpx0.851/vpy-0.268`⋯)
3. 用 shader 寫 rounded-box SDF 遮罩做圓角
4. 手切自訂 8 控制點 BufferGeometry,斜角要貼合螢幕開口
5. **卡頓、銳角、飄移,整個方案放棄**
6. 改成 DOM 影片疊層:每幀把 3D 螢幕的控制點投影成畫面像素,動態設定 `clip-path`
7. 錨點還是用猜的 → 改成錨到 GLB 裡真正的螢幕面 mesh(`Object_12`)
8. 開始窮舉角度:+3 度 → 削到角落 → 0 度 → +1.5 度 → −2 度
9. 圓角改成 24 個控制點,但 `clip-path` 迴圈還寫死 8 → **影片被裁成頂端一條細線**
10. 修好,改成四角定位,二次貝茲做圓角
11. 右下角單獨再調

十一次。到這裡我已經沒有更好的想法了。

然後 Claude Code 做了一件我沒想到的事:**它做了一個工具,讓我自己用滑鼠把四個角拖到定位。**

畫面出現四個藍色把手,我拖,它即時把座標反投影回 3D mesh 上重建裁切,左上角同步顯示一組可以直接複製回程式碼的座標陣列。我拖了幾下,複製,貼上。

下一個提交是:

> 影片四角採用使用者用 `__cornerTool` 拖曳對位後的精確值,精準貼合螢幕

![首頁分鏡第 03 階段「發光線稿」:相機拆成零件,以線框呈現](/assets/blog/blueprint.webp)

那一整天算不出來的東西,最後的解法是不算了——做一個介面,讓看得見畫面的人來判斷。

我原本以為 AI 寫程式的價值在於它算得比我準。那天我發現不是。它的價值在於它知道什麼時候該停止計算、把判斷權交回給我,並且順手把交接的工具也做好。

## 失敗與回滾

7 月 22 日,我試著讓它自動重新設計「六大功能」區塊。結果不能用。

提交記錄:

> 還原六大功能區:移除失敗的編輯設計自動實驗(583c6f7)

回滾之後改成手工做:先鋪一層瑞士編輯格線,再讓六隻角色一隻一隻破格——01 坐在格線上把 hairline 壓彎、02 雙手吊在格頂引體向上、03 趴在橫線上、04 單手吊線盪鞦韆、05 走鋼索、06 倒掛在線下。六個獨立提交,一隻一隻來。

![六隻零件怪獸各自用不同姿態破格,腳下那條 2px 全黑的線是瑞士編輯格線](/assets/blog/creatures.webp)

比自動重設計花了更多時間,但成果好很多。這件事教我的分工是:**結構可以交給它,品味不行。**

## 誠實性也是工程問題

有幾個提交我特別想提:

> `PeakOps P4:誠實性修正(移除不實與自相矛盾的陳述)`
>
> `Pricing 重做:⋯ 移除不實承諾`
>
> `案例頁 Phase B 下半:作品卡狀態、案例編號、Lightbox 說明(誠實不捏造)`

寫行銷文案的時候,很容易滑向那種聽起來很厲害但其實沒有內容、甚至和前段互相矛盾的句子。Claude 有指出這些地方。這不是我要求的功能,是它在改稿過程中主動提的。

到今天為止,網站上還有一批「需要事實才能寫」的項目是空著的——合約條件、保證條款的性質、資安的具體宣稱、案例的成效數字。那些我還沒有可以拿出來的憑據,所以寧可不寫。這也是為什麼 [方案說明](/pricing) 上寫的是「依需求報價」而不是一個數字。

一個新公司的官網最容易犯的錯,就是把自己講得比實際大。一個會抓到這件事的協作者,比多一個會寫 CSS 的協作者有價值。

## 我們發展出的工作方式

### 驗收探針

專案裡有一個 `.peakops-audit/` 目錄,放的是不在網站路由上的驗收頁。無頭瀏覽器幾乎不跑 `requestAnimationFrame`,所以這些頁面支援 `?step=N` 參數:把 rAF 換成固定 dt 的手動時鐘,推 N 幀,截圖因此可重現。

這是為了讓「動畫對不對」這種主觀問題,變成可以逐像素比對的問題。

### 代理併行審查

8 月 3 日的手機版總審查,提交寫著:

> 32 筆定罪逐一修復 + 複驗(55+8 代理兩輪)

派出多個代理去跑不同視口與情境,回報問題清單,逐項修復後再複驗一輪。

### 共用詞彙

「母動畫」是捲動驅動的主軸,「子動畫」是每一幕內部自己跑的時間軸。這組詞是做到一半自然長出來的,之後我只要說「這一幕的子動畫凍結了」,它就知道要去看哪裡。

### 追根因,不修表象

8 月 5 日有一個提交:

> 機器人「沒站在線上」的真因:它們腳下那條線幾乎看不見

我回報的是「機器人沒站好」,實際問題是線的對比度不夠。

## 一個私心

[關於我們](/about) 頁上有一個機器人,站在自己的工作間裡。它叫 Allen。

它的工作間有 40 個手工拆出來的圖層,會隨訪客當地的時間變成白天、黃昏或夜晚。窗外的雲會飄,夜裡有星星和一顆慢慢升起的月亮;雲會擋住星星,月亮從雲後面浮起來的時候雲會微微透光,月光也會打在窗外的建築上。有六個地方可以點——窗戶、檯燈的開關、馬克杯、海報、控制台、工具排——點下去它會轉頭看過去。

![Allen 的工作間,白天](/assets/blog/allen-day.webp)

![同一個工作間,夜晚:星星、月亮與從窗口灑進來的月光](/assets/blog/allen-night.webp)

技術上這是全站最麻煩的一塊。整套天色不是準備三張圖片,而是用 multiply 壓暗加 screen 提亮兩層分級圖,在 sRGB 空間精確推導出來(實測平均差 0.3 階)。

素材產生器會自我驗算:把底板加元件貼回去,和原稿逐像素比對。這裡有一個細節值得說——**關卡看的不是 RMSE**。轉檔把整張放大再換算回來,每一條描邊都會差個 1px,那種差異 RMSE 看得到、眼睛看不到。真正要擋的是「一整塊東西不見了」,所以關卡是「差異超過 60 的連通區域必須是 0 塊」。目前 RMSE 是 3.74,不合格區域 0 塊。

這一段沒有任何商業理由。我只是想在自己蓋的網站裡放一個自己。
